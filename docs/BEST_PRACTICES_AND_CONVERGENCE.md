# 最佳实践与收敛原则

## 1) 产品层收敛

- 单一入口：所有运维动作尽量在面板完成
- 降噪优先：避免页面过长，采用 Tab 分区
- 可观测性优先：关键动作必须有实时日志反馈

## 2) 架构层收敛

- “前端展示 + 后端编排 + SSH执行”三层分工固定
- 后端返回 JSON 规范化，避免前端解析歧义
- 高危操作（删除、重启）必须显式动作入口

## 3) 安全层收敛

- 默认开启 Basic Auth
- 强制输入校验（服务名、容器名、路径、端口）
- 机密仅放 `.env` 或部署侧配置，不落仓库

## 4) 运维层收敛

- 优先域名/路径代理，减少直连端口暴露
- Nginx 配置通过“生成文件 + `nginx -t` + reload”三步应用
- 任何部署动作需包含“可回滚版本标识”

## 5) Agent 协作收敛

- 先读文档再改代码
- 每次改动都附带“验证步骤”
- 保持风格一致：命名、输出、错误文案、按钮语义

## 6) 变更质量门槛

- 前端改动：必须移动端可用、按钮可点击、错误可理解
- 后端改动：必须参数校验、异常兜底、返回结构稳定
- 部署改动：必须给出可复制命令与成功标志

## 7) 建议的后续演进

- 增加 RBAC（只读/运维/管理员）
- 增加操作审计（谁在何时做了什么）
- 增加代理规则测试按钮（连通性校验后再应用）
- 增加健康检查与告警联动
